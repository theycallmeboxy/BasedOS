# GKD 350H Ultra: on-device recon (Phase 0)

Collected 2026-11-16 over SSH from a GKD 350H Ultra on its stock firmware, using
`tools/dev/recon.sh` (read-only) and `evtest`. **No SD card was inserted**
during this run. Everything below marked **verified** was read on the device; anything
marked *inferred* is a conclusion drawn from what was read, not tested.

The raw output is kept out of the repo because it holds the device serial number,
Wi-Fi MAC and nearby network names. It is regenerated by running `recon.sh`.

## Boot chain (read-only from eMMC, 2026-11-16)

- No SPI flash on the board (no `/proc/mtd`, no SPI bus). The whole Rockchip boot chain sits in the eMMC user area, before p1 (MBR partition table, no GPT):
  - sector 64: Rockchip idbloader (`RKNS`, DDR init + SPL). **Rockchip vendor U-Boot SPL 2017.09, built Jul 17 2026**, with a device tree based on `radxa,rock-4d`.
  - 8 MiB: U-Boot FIT (U-Boot + BL31 + OP-TEE).
  - 16 MiB (sector 32768): p1.
- **SPL `u-boot,spl-boot-order` = `"/mmc@2a310000", "same-as-spl"`**: the SD slot first, then the eMMC it was loaded from (decoded from the FDT property bytes). The U-Boot device tree's copy reads `/mmc@2a310000`, `/spi@2a340000/flash@0`, `flash@1`, `same-as-spl`.
- U-Boot's environment: `bootcmd=run distro_bootcmd`, `boot_targets=mmc1 mmc0 mtd2 mtd1 mtd0 usb0 pxe dhcp`, `bootdelay=0`. Kernel DT aliases: `mmc0` = `2a330000` (eMMC, `dwcmshc`), `mmc1` = `2a310000` (SD slot, `dw-mshc`), `mmc2` = `2a320000` (SDIO Wi-Fi).
- Stock `boot.scr` (on p1) loads `Image` and `rk3576-gkd-atom{,-hdmi,-usbdp}.dtb` from `mmc 0:1` and `booti`s with no initrd.
- Consequence: both the SPL and U-Boot try the SD card before the eMMC. A card with a U-Boot FIT at 8 MiB boots from the card; a plain spruce card has neither a FIT nor `boot.scr`/`extlinux`, so it falls through to the eMMC. GammaOS Next ships an SD-card image for this device that boots without touching stock, consistent with this.
- Stock's initramfs (a gzip cpio built into `Image`) passes no `boot=`/`disk=`. It runs `fsck -y` on `/dev/mmcblk0p1` and `p2`, then mounts them as `/flash` and `/storage`, by name. `fs-resize.sh` hardcodes `mmcblk0` too. Because the kernel numbers `mmcblk` by the DT aliases (`mmc0` = eMMC), this always means the eMMC, whatever device U-Boot booted from. The rescue card works around it by swapping the aliases in its own DTBs (see recovery.md).
- Stock's `automount` (games card) skips any disk that has `boot0` ("might be Android") or is smaller than about 8 GB, and the udevil rule only handles `sd*`/`sr*`. So a stock system booted from the SD card never mounts the eMMC.
- The eMMC hardware boot partitions (`mmcblk0boot0/1`, read-only in Linux) are **not** empty, as an earlier note said. Both hold the same ~556 KB: an **Amlogic GXL BL2** ("`@AML`" header, "Built: 17:21:16, Mar 19 2021"). The chip (manfid `0xea`, name `SPeMMC`, date 03/2022) was evidently pre-programmed for, or recycled from, an Amlogic product. The RK3576 BootROM loads from the user area, so this is dead weight. Leave it alone. It is in the backup.
- Recovery modes (tested, see recovery.md): hold **Menu + Home** at power-on for U-Boot USB mass storage of the whole eMMC (`2207:0010`), or **Volume Down** for maskrom (straight to the boot ROM, apparently a hardware maskrom key) (`2207:350E`). Use a USB-A to C cable. Long-press power to exit.
- The USB-C controller (`usb@23000000`) is OTG with a UDC present, so it can act as a USB device (needed for Rockchip maskrom recovery).

## Sleep (verified on BasedOS, 2026-11-16)

- `mem_sleep` = `s2idle [deep]`. Deep suspend (`echo mem > /sys/power/state`) enters and exits
  cleanly. The display and Wi-Fi (bcmdhd, same lease) come back, and the power button wakes it.
- Deep-sleep wake mask: `rockchip-suspend/rockchip,wakeup-config = 0x100`. The PMIC
  (`pmic@23`, GPIO0_A6) and the RTC (`hym8563@51`, GPIO0_A5, `wakeup-source`) both sit on
  always-on GPIO0, and both wake the board.
- The **hym8563 alarm has minute resolution**: it fires at the start of the target minute, up to
  59 s early. spruce's `device_woke_via_timer` allows 10 s, so the GKD platform rounds wake
  alarms up to a whole minute. With "Shutdown after sleeping", the device then sleeps, wakes on
  the RTC and powers off cleanly (`rcK` ran, and the card was clean on the next mount).
- **Every resume reports a power-key press**, the RTC wake included. The rk805 pwrkey node
  (event0) emits KEY_POWER down/up as the system wakes, though nobody pressed it. This is likely
  the Rockchip BSP waking Android userspace. spruce ignores it after its own sleeps (its
  post-wake cooldown), but a suspend started outside spruce is followed by spruce going straight
  back to sleep. Seen 2026-11-16: an RTC wake at 22:12:49 logged power_key_down/up in
  spruce.log. Test suspends through spruce (tap power), not with a raw `echo mem`.
- Deep sleep evidence: `PM: suspend entry (deep)`, CPUs 1-7 taken down through PSCI
  (`psci: CPUn killed`) before the firmware's system suspend, `suspend_stats/success` counting up.
- The kernel has a `reboot-mode` node (`syscon@26024000/reboot-mode`: normal, loader, bootloader,
  recovery, fastboot, ums, winusb, charge, quiescent, watchdog), so `reboot loader` and others
  should work. Not tried yet. (Earlier searches missed it: BusyBox `find` doesn't follow the
  `/proc/device-tree` symlink, so search `/sys/firmware/devicetree/base` instead.)

## Incident during recon

While checking `ra64.universal`, Git Bash rewrote the remote path `/tmp/spruce-probe/...`
into `C:/Users/.../Temp/spruce-probe/...`. SFTP took that as relative to root's home and
wrote the 15 MB file to **`/storage/C:/Users/.../ra64.universal` on the eMMC**. The tree
held only that file and had not existed before (it wasn't in the recon listing).
It was removed with `rm -r "/storage/C:"`, and `/storage` usage is back to the 923.4 MB
recorded before. `gkdssh.py` now refuses non-absolute or Windows-style remote paths,
refuses writes outside `/tmp`, `/run`, `/storage/games-external` and
`/storage/.config/system.d`, and refuses `/storage/games-external` when no card is
mounted.
